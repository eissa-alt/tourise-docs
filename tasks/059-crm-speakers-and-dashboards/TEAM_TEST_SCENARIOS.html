Before you start (once, by an admin):

  1. CRM, Settings: add the Source List and List Provided By values your README lists. A contacts file that names a value not on the list is refused.
  2. Roles: for any role other than Super Admin, tick the CRM boxes it needs: View, Create, Update, Delete, Invite, View dashboard (Contacts), and the speakers' ones (View speakers, Add and import speakers, Edit speakers, Delete speakers, Invite speakers, View speakers dashboard).

1. Tabs and pages

#DoExpected
1.1Open CRM from the sidebarThe tabs Contacts, Speakers, Settings; Contacts opens on its Dashboard. No Imports tab.
1.2Click Data, then DashboardThe table, then the charts. Filters set on one stay on the other.
1.3Open SpeakersIts own Dashboard and Data, with the speakers' columns and filters only.
1.4Log in with a role that has only the speakers' boxesOnly the Speakers tab (and Settings if ticked); the Contacts pages are not reachable.

2. Contacts: add, edit and lists

#DoExpected
2.1Add contact with a required field emptyRefused, each field named; required fields are marked as in the client's sheet. Email or Mobile: one is enough.
2.2Pick a CategoryIts Sub-category is asked only when it has some, and offers only those under it. Industry and Sub-industry the same.
2.3Pick a Country of ResidenceRegion fills itself (MENA, Europe...).
2.4Every list field (Title, Nationality, Sector, Seniority, Tier...)A dropdown of the system's own values, the same as on Guests. Tier only for a role with View tier.
2.5Edit a cell in the table, or a field in the contact's windowSaved in place; a wrong value refused with the reason.
2.6ColumnsHide and show columns; kept for you.
2.7Edit selected (bulk) on a few contactsOne change to all; those the rules stop are listed with the reason.
2.8A role limited to some categoriesSees and edits only those categories' contacts; another category is refused.
2.9History in a contact's window; Audit trail on the pageEach change, who and when.

No tiles.
